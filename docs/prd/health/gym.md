## Scope

### Base (openGym parity)

| Feature | Notes |
|---|---|
| Exercise library | 1,324 catalog exercises + custom ones (name + body part is enough). Search, filter by body part / equipment / muscle, "equipment I have" filter, favorites, per-exercise notes. |
| Routines | Ordered entries; per entry: mode (reps / timed / cardio), sets, reps or rep range, weight, duration, distance, rest, superset group, per-side, bodyweight flag, progression override, increment, target RPE, loading scheme. Starter templates (PPL, Upper/Lower, Full body, 5×5, Greyskull, 5/3/1 BBB). |
| Weekly plan | A routine per weekday + per-date overrides (move a missed session, declare a rest day) without touching the plan. |
| Live workout | Starts today's routine (or an empty session). Optional weigh-in first (writes a `health_metrics` weight row). Sets pre-filled from the prescription with its reason. Log weight/reps, timed holds with a work timer, cardio time + distance. Optional RIR/RPE per set. Rest timer (sound, optional notification), screen kept awake, supersets with rest after the pair, warm-up set generator, plate calculator, live PR badges. Finish summary: PRs, volume, muscles trained. Resumable after reload. |
| Progression engine | Policies: off, linear, Greyskull LP (AMRAP last set, double jump, 10 % reset), double progression (rep range), add-time. Missed reps never advance; repeated misses deload; bodyweight work progresses reps then sets. Every target carries "why". |
| Estimated 1RM & PRs | Epley / Brzycki / Lombardi, refuses > 12 reps. PR types: e1RM, heaviest, best set volume, most reps at a weight, longest hold, longest distance. 1RM calculator. |
| Stats | Year activity heatmap (minutes trained), muscle map (front/back, male/female) over week / month / all — shaded by sets, naming untrained muscles, also shown for a routine while editing and on finish. Weekly volume, e1RM curves, effort distribution, weekly streak. |
| Body weight | Existing `health_metrics` weight entries + a goal weight line; changes colored by direction toward the goal. |
| Import / export | Strong, Hevy, FitNotes CSV (incl. RPE); Apple Health body weight; shareable plan file (routines + week, merges on import); printable plan; full gym backup JSON. Unrecognized exercise names become custom exercises — nothing in a file is dropped. |

### Advanced packs

| Pack | Features |
|---|---|
| Smarter programming | Training maxes + 5/3/1 (main sets 65–95 % with AMRAP, BBB 5×10, FSL 5×5, deload week, TM bumps derived from AMRAP results). Training blocks (mesocycles) with weekly set ramp and a planned deload week. RPE-based autoregulation (target RPE → load from e1RM via an RPE/reps chart). Plate calculator, warm-up generator. |
| Recovery & analytics | Weekly hard sets per muscle vs MEV / MAV / MRV landmarks (editable overrides). Push/pull and quad/hamstring balance. Acute:chronic workload ratio from session-RPE load. Daily readiness check-in (sleep quality, energy, soreness, stress, motivation) + last night's `sleep_hours` metric → readiness score and a train-hard / normal / easy / rest recommendation. Gym insights feed (stalled lifts, neglected muscles, volume outside landmarks, imbalance, load spikes, deload due, PRs, consistency vs weekly goal, weight-goal pace) — dismissible, same pattern as finance insights. |
| Body composition | Tape measurements (neck, waist, hips, chest, arms, thighs, calves …) and measured body-fat %. Derived: BMI, US-Navy body-fat estimate, lean mass, FFMI (normalized), waist-to-height. Strength standards: DOTS score for the big three and per-lift bodyweight-ratio levels. |
| Camera rep counter | MediaPipe pose landmarks from the webcam (model already vendored under `public/models/`, never a CDN — nothing leaves the machine). Counts reps for squat, push-up, curl, overhead press, lunge, hinge, pull-up, lateral raise, jumping jack; scores range of motion per rep and flags form issues (shallow depth, hip sag, partial lockout). Fills the active set's reps, marked `tracked_by = camera`. |

### Known limits

- No push notifications while the app is closed (local-only, no push server). Rest-timer alerts use the browser Notification API while the tab is open; "planned workout not logged" shows as an insight instead of a reminder.
- No exercise animations (media license, see above).
- Weights are kg only.

## Data model

All tables are `health_*`, schema under `src/modules/health/db/schema/gym/`, created by migration `drizzle/0025_health_gym.sql`.

| Table | Purpose |
|---|---|
| `health_exercises` | Catalog (seeded at runtime by `catalog_key`) + custom exercises |
| `health_routines`, `health_routine_exercises` | Templates and their ordered entries |
| `health_week_schedule`, `health_schedule_overrides` | Weekly plan + per-date overrides |
| `health_workouts`, `health_workout_exercises`, `health_workout_sets` | Sessions; entries snapshot the prescribed target and its reason |
| `health_programs`, `health_training_maxes` | Blocks / 5/3/1 cycles; TMs the user set |
| `health_body_measurements` | Tape measurements + measured body fat |
| `health_readiness_checkins` | Daily 1–5 self-rating |
| `health_gym_settings` | Single-row preferences (sex, height, goal weight, effort scale, rest, formula, bar & plates, owned equipment, weekly goal, sleep target, toggles) |
| `health_volume_landmarks` | User overrides of per-muscle MEV/MAV/MRV |
| `health_gym_dismissed_insights` | Dismissed insight ids |

Derived, never stored: PRs, e1RM, current program week, effective training max after cycle bumps, muscle volume, readiness score, body composition, insights.

## Additions (2026-10-05)

Requested after the first build: cardio speed/pace, weight-change colours toward the goal, a hard-sets view of the muscle map, pounds, and camera upgrades (voice coach, hands-free auto-log, set replay, progress photos).

### Weight units — the one convention every page follows

- **Storage is always kg.** `health_gym_settings.weight_unit` (`kg` | `lb`) only changes display, input and default load jumps.
- **Display:** `formatWeight(kg, unit)` / `toDisplayWeight(kg, unit)` from `engine/units.ts` (lb to 0.1, so 225 lb round-trips exactly).
- **Input:** parse the typed number, then `fromDisplayWeight(value, unit)`, rounded to grams, before calling any action. Actions and services only ever see kg. (The full settings form is the one exception: it posts an `inputUnit` field and the action converts.)
- **Steps:** `defaultIncrementKg(bodyPart, unit)` / `tmIncrementKg(bodyPart, unit)` give 5/10 lb for lb users; percentage loads round to `smallestStepKg(unit)` (2.5 kg / 5 lb). Engine reasons, record contexts and insights are generated in the user's unit.
- Switching unit on an untouched setup swaps bar and plates to that unit's standard set (45 lb bar; 45/35/25/10/5/2.5 lb plates).
- Body measurements stay in cm.

### Camera additions

- **Voice coach** (`voice_coach` setting): browser speech synthesis speaks rep counts and form cues; nothing leaves the device.
- **Hands-free auto-log** (`camera_auto_log` setting): inside a workout, once you stop moving the counted reps are logged to the open set after a short cancelable countdown, and the rest timer starts.
- **Set replay:** the set is recorded on-device (MediaRecorder) with its pose timeline; replay plays it slowed down with the skeleton redrawn over it. Discarded on close unless downloaded.
- **Progress photos:** `health_progress_photos` stores downscaled JPEG/WebP inside the encrypted database with the pose landmarks found at capture (used to line photos up for comparison). Served only through `/api/health/progress-photos/[id]` behind `requireUnlocked`, `Cache-Control: private, no-store`.
